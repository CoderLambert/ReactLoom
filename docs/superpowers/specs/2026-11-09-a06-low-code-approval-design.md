# React Flow 表单与审批低代码工作台

用户确认的场景：配置字段、必填规则、审批人、金额条件、通过/驳回路径；发布后提交工单、实际流转并查看操作记录。

## 方案与边界

采用现有 A06 条目内的 React + React Flow 受控编辑器、JSON 定义和确定性运行时。对比页面布局搭建器和新闻自动化，表单审批同时体现动态表单、图配置和执行，符合用户选择。不添加其他模板或通用 Lab 运行协议，不新增依赖。

本地项目使用独立 localStorage key，显式保存；不访问外部服务。审批角色由操作者切换，明确标注为本地演示，不作为鉴权。真实上线需服务端重复校验、身份授权、数据库事务、审计及幂等。浏览器关闭后数据仍在；存储失败展示错误并保留内存状态。

## 定义与发布

schemaVersion=1，表单字段限 text/number/select；节点限 start/approval/condition/end；条件限数值 >= 阈值。字符串、集合、JSON 大小均设上限。基础层提供线性审批，业务层提供金额条件和财务审批，边界层开放 JSON 导入导出与错误检查。三层共用配置和执行实现，存储按层隔离。

节点位置、id、白名单 data、端口连线作为业务定义；不持久化 React Flow 的测量、选择或拖动字段。条件节点有 yes/no 出口，其他非结束节点只有 next 出口；禁止环、自环、重复出口、结束节点出边和起点入边。发布必须保证唯一起止、所有节点可达、所有出口完整、审批人及数值条件字段有效。删除节点清理关联边，删除或改变字段使引用条件失效时禁止发布。

发布生成独立递增版本快照。修改草稿不改变已发布版本；提交工单复制发布快照及校验后的表单值。已有工单永远按自己的定义流转，拒绝错误审批角色、重复操作和终态操作。条件自动求值，审批节点等待人工，驳回直接终止，通过到结束才完成。记录时间、节点、角色、动作及说明。

## 界面与验收

配置、申请、工单三页签。配置页含字段列表、实际 React Flow 自定义节点及明确高度画布、属性面板、键盘连线与边列表、发布错误；申请页由已发布字段动态渲染；工单页提供角色切换、意见、通过/驳回及历史。

Node 策略测试覆盖发布校验、双分支、驳回、快照隔离、错误角色、重复处理、非法导入、存储恢复。Playwright @A06 使用真实 SDK 验证配置改变实际表单、发布提交流转、刷新恢复、草稿不影响旧实例、非法连接/删除和无页面异常。类型检查与构建检查真实集成。无正式 verify:record 收据时 verification.json 不标 PASS。
