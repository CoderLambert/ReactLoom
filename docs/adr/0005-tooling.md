# ADR 0005: Tooling

Biome replaces ESLint and Prettier for this new repo. Lefthook replaces Husky and lint-staged: it formats staged files with Biome, then typechecks and tests the packages changed since `HEAD`. TypeScript 7 has no stable programmatic compiler API, so type-aware `typescript-eslint` is not a practical default. `tsc` remains the typecheck. Shared presets set `incremental` so repeat runs reuse `.tsbuildinfo`. The SPA dev server uses vite-plugin-checker 0.14, which shells out to `tsc` for the in-browser overlay and does not run ESLint or Biome. Turbo is not used; the workspace is small and `pnpm --filter "...[HEAD]"` already limits work to affected packages. Click-to-source is on by default. `code-inspector-plugin` runs on the Vite and Next.js dev servers, and `react-native-dev-inspector` runs on Metro. The bundler points the inspector at `scripts/open-in-editor.mjs`, which opens a listening Neovim (`nvim --listen` or `.nvim.sock`), then a running Cursor or VS Code. `.env.development` leaves the editor unset. Production builds omit the inspectors. React Scan 0.5.7 uses its documented module import in the SPA entry and its documented Next.js client component. Production builds alias that import to an empty module. Expo does not load it: 0.5.7 has no React Native export, and the native preview is unmerged. why-did-you-render 10.0.1 runs on Expo in development only, because v10 needs a JSX importSource that Vite 8 and Next.js 16 Turbopack cannot apply without running ahead of React Scan or leaving SWC. SPA and SSR use React Scan for the render cause and the changed props. `pnpm analyze` is rollup-plugin-visualizer, Next's `next analyze --output` (with `@next/bundle-analyzer` kept for `next build --webpack`), and Expo Atlas. `useWhyDidYouUpdate` in `@reactloom/devtools` is an opt-in console diff and is not imported from an app entry.

Tailwind CSS v4 uses `@tailwindcss/vite` in the SPA and `@tailwindcss/postcss` in Next.js. The mobile template uses React Native styles so Metro does not depend on NativeWind.

Web tests are Vitest plus Testing Library, MSW for the SPA integration test, and Playwright with axe. Storybook 10.6.1 runs on the SPA with `@storybook/react-vite` and on SSR with `@storybook/nextjs`, both with the a11y addon and the shared MSW handlers. `@axe-core/react` logs in those dev servers only. Expo does not load on-device Storybook, MSW, or `@axe-core/react`; it keeps `EXPO_PUBLIC_USE_FIXTURES` and the Maestro flow. Bundle scripts fail the build when gzipped JavaScript exceeds the budget in each template.

Changesets versions the library and the CLI. Renovate groups dependency updates; see the README. This repository does not publish packages.
