## Architecture

Library Lab is a private Vite app (`@reactloom/library-lab`) on ports **4319** (app), **4320** (F11 MSW runner), and **4321** (C13 Gantt runner). `scripts/serve-lab.mjs` starts those three configs together for `dev` and `preview`. `packages/*` is in `pnpm-workspace.yaml`, so a root install includes the lab. `create-reactloom` has no `library-lab` reference, and the lab is not in a template `template.json`.

Generation is one pipeline, `scripts/generate.mjs`:

- Every directory under `entries/` must be `{entryId}-{slug}`, pass `validateEntry`, and (for the expected 119) pass `scripts/entry-gate.mjs`: `guide.md`, `agent.md`, `AGENTS.md`, `verification.json`, and exactly one basic, business, and advanced demo whose `entryPoint` is listed in `sourceFiles`.
- React demos become lazy imports in `src/generated/loaders.ts` (gitignored). Worker demos would become `worker-loaders.ts`. This tree emits **318 loaders and 0 workers**.
- Displayed source is copied to `public/raw/<ID>/sources/<original>.txt`. HTML is not published as a page.
- `catalog:check` is an in-memory shape and dependency-contract check. It does not diff generated files, because those files are gitignored. `catalog:index` (`root-catalog.mjs --committed`) is what checks the committed `LIBRARY_CATALOG.md` and `library-catalog.json` before regeneration.

`src/components/demo-host.tsx` mounts a demo only after an explicit click, and a scenario change clears that authorization. Run policy in `src/lib/demo-policy.mjs`:

| `executionKind` | What the page does | Count on this tree |
| --- | --- | --- |
| `react` | Lazy-load the real module after click | 106 libraries, 318 demos |
| `node-ci` | Show a copyable command. The page does not spawn a process | 12 libraries, 36 demos |
| `browser-frame` | Fail closed, except the registered C13 Gantt iframe | 1 library (C13), 3 demos |
| `worker` | Registered worker factory | **0** |

F11 is `node-ci` plus a hardcoded `IsolatedMswPanel`. The panel only starts a session from `http://127.0.0.1:4319` into `http://127.0.0.1:4320`, with a per-session Service Worker scope. C13 is the only `browser-frame` entry, and `isRegisteredGanttDemo` accepts only `examples/demo.tsx` at the three fixed levels. 110 of 119 entries point all three levels at one `entryPoint`; the other 9 are Node/CLI workshops with a file per level (`D16`, `D21`, `F04`, `F05`, `F10`, `F12`, `F13`, `F15`, `F16`). That shared-file shape is the protocol in `docs/library-lab/COORDINATION.md`, not a missing demo.

Routes are `/` and `/libraries/$slug` (`src/app/router.tsx`). Unknown paths use the router not-found view. There is no third route that the catalog links to and the router drops.

### High

**1. Status documents contradict `main`.**

`docs/library-lab/COORDINATION.md` says the integration branch is `feat/library-lab`, the PR to `main` stays Draft, and `main` must not be changed. `docs/library-lab/IMPLEMENTATION.md` and `docs/library-lab/REPAIR.md` repeat “PR #8 (Draft)” and “do not change main”. `REPAIR.md` still says the root lockfile has no trustworthy Lab importer and that this round did not write one. `progress/PLATFORM.md` says a real Lab importer is still missing, and that full typecheck, Vite build, SDK, Chromium, and the six risk slices are NOT_RUN.

Observed on this `main`:

- `HEAD` is the merge of PR #8.
- `pnpm-lock.yaml` has an importer at `packages/library-lab:` and resolved packages that the notes say are absent, including `msw@3.0.3`, `monaco-editor@0.57.0`, `papaparse@5.7.0`, `vitest@5.0.5`, `@uppy/core@6.1.0`, `@ffmpeg/core@0.12.10`, and `xlsx` from `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` with an integrity hash (`pnpm-lock.yaml` around the `xlsx@https://cdn.sheetjs.com/...` resolution).

An agent that trusts `COORDINATION.md` will treat the lab as unpublished and the install as blocked. Both are false on this commit.

**2. A green CI run is not visible as per-entry evidence, and it does not cover 119 libraries.**

`scripts/verification-contract.mjs` keeps PASS only when `sourceFingerprint`, the exact allowlisted command, and a receipt plus log under `docs/library-lab/evidence/runs/` all match. That directory is absent. Readiness therefore stays at PASS 0, including for A01, whose `verification.json` still says the echarts install is missing, after `sdk-runner --entries=A01` passed locally in this audit (real `echarts/core` import, SVG renderer, dispose).

That split is intentional: CI logs are not receipts, and a repo-wide `pnpm build` is not an entry-scoped build receipt (`verificationCommand` for `build` is `pnpm build`, while browser is `playwright test --grep @ID`). The in-app panel and `find-library` read the entry file or the generated downgrade, not the Actions log. Consequences:

- The homepage (`src/app/home.tsx`) shows `{runnable}` as “已有示例”, and `hasDemo` is true whenever any demo has an `entryPoint`. On this tree that number is **119**, including 12 Node-CI libraries that never mount a widget. The hero copy says the tools are “在这里真正用起来。”
- `LIBRARY_CATALOG.md` and `packages/library-lab/README.md` do say that 119 entries and 357 scenarios are not SDK or browser passes. The README is the accurate surface. The hero and the stale progress files are not.
- Playwright’s own CLI exits 1 when `--grep` matches nothing (`playwright test --list --grep '@A02\b'` → `Error: No tests found`, exit 1). A missing browser tag does not silently pass. It also means most entries have no browser tag to select.

**5. The lab is on the default workspace install path, including a GPL binary and a CDN tarball.**

Root `.github/workflows/ci.yml` runs `pnpm install --frozen-lockfile` with no filter and never mentions `library-lab`. Template verify jobs therefore download the lab’s dependency tree even though they do not test it. That tree includes:

- `@ffmpeg/core@0.12.10` (devDependency, GPL-2.0-or-later). `scripts/prepare-ffmpeg-core.mjs` deletes any generated `public/ffmpeg-core/` unless `LIBRARY_LAB_FFMPEG_CORE_LICENSE_REVIEWED=true`, and it checks the package name, version `0.12.10`, and a license string starting with `GPL-2.0` before copying. The wasm is gitignored. The package is still fetched into `node_modules` on install. The demo does not fall back to a CDN if the local files are absent; load failure is shown as a status string.
- `xlsx` resolved to the SheetJS CE tarball on `cdn.sheetjs.com`, with a lockfile integrity hash (`src/lib/package-source.mjs` allows only version `0.20.3` at that exact URL). The frozen install succeeded in this environment, so the tarball was reachable today. A CDN outage fails the root install, not only the lab.

`library-lab.yml` runs on pull requests to `main` and on pushes to `feat/library-lab`. It does not run on push to `main`. Protection is PR-time. The catalogue job correctly runs `npm test` and `policy-runner` without installing SDKs.

## Recommendations

Do these first. Do not add entries, and do not mass-edit `verification.json` to PASS.

1. **Replace the status block in `COORDINATION.md`, `IMPLEMENTATION.md`, `REPAIR.md`, and `progress/PLATFORM.md`.** State that PR #8 is merged, the lockfile importer exists, and run 41779873259 passed install, typecheck, build, the 52 existing SDK files, and the 45 existing Playwright tests on this lab tree. Keep the sentence that this is not 119 SDK/browser receipts.
2. **Point the homepage at readiness, not at “已有示例” alone.** Show source-complete, React-mountable, Node-CI, and receipt-backed PASS as separate numbers. Soften “真正用起来” so it matches the README.
3. **Clear stale BLOCKED notes** whose only reason is “DNS”, “lockfile missing”, or “add msw/vitest/monaco”, now that those packages resolve. Leave status `NOT_RUN` until `verify:record` writes a real receipt. Delete or rename `content` so the only PASS strings in `verification.json` are receipt-backed sdk/build/browser results. Today there are zero of those.
4. **Record receipts only for commands that already exist and already passed**, one entry at a time, starting with the six first-risk ids: A01, B17, C01, D03, E05, F11. A01/B17/C01/D03/F11 have Node suites that passed in CI; E05’s evidence is the `@E05` Playwright test, not a Node suite. Do not copy the repo-wide Playwright exit code onto an entry that has no `@ID` test.
5. **Add Node or browser coverage where an agent is likely to copy code and no suite exists.** A02–A17 and the B group are the hole. F05’s `verify.mjs` never enters `test:sdk` because of the filename allowlist; either give it an allowlisted suite or document that CLI workshops are `cli-runner` only.
6. **Stop making every template install pay for the lab.** Move `@reactloom/library-lab` out of the default `packages/*` install that root CI always performs, or document and accept that `pnpm install` fetches a GPL FFmpeg core and the SheetJS CDN tarball. The staging flag is the right redistribution gate; it does not shrink the install.
