## 内容改写标准

每篇用一个明确工程问题和贯穿案例串联：用途与选型 → 核心模型 → 最小接入 → 业务变化 → 关键取舍。读者能解释每段关键代码的输入、处理和结果。

标题使用具体能力或问题。前置知识只补理解本库所需的部分。重要约束就近解释；维护收据、历史整改、内部通道和旧分支记录归维护材料。核心断言查对应版本的官方文档、类型或源码，资料版本差异显式标明。

每个 Demo 描述包括问题、操作步骤、预期可观察结果、关键源码和运行前提。复杂库按核心能力、业务集成、重要工程问题递进；简单工具可用一个完整输入输出实验。小工具不能通过增加业务故事和清单填满三层；复杂库也不能只换数据量或文本就算业务进阶。

源码正常排版并能迁移。目标库真实使用，后端 fixture 说明范围；截图、输出、性能数字和产物必须来自实际执行。CLI 工具交付准确的 cwd、命令、退出状态、输出与产物解释。

## 公共平台实施切片

### 1. Demo 协议与讲解入口

先调整公共类型、校验、生成器、测试与规则文件，再修改条目：

- 完整条目允许 1–3 个 Demo，demoId 和已提供的 level 不重复，每个源入口仍必须包含在 sourceFiles 中。保留 basic/business/advanced 的兼容含义，完整条目至少提供 basic。
- 给 Demo 增加学习目标、操作步骤和可观察结果的说明。只维护实际可执行源码，文档中的片段与对应源码建立链接。
- 页签顺序为 docs/demo/readme/website/agent/related，文案为讲解、Demo、官方 README、官网预览、Agent 指南、相关资料。目录默认进入讲解；明确指定 tab=demo 的旧链接继续有效。
- 合并或移除场景前检查其深链接，保留可用映射或回退到该库第一个有效 Demo。
- 生成目录中的 counts、选择器、检索和测试 fixture 同步处理可变 Demo 数量，禁止用生成后的索引掩盖提交前的不一致。

### 2. 官方 README 快照

在条目 metadata 中添加向后兼容的官方资料信息；尚未迁移的旧条目允许明确缺失，不通过“新增资料完整”的验收。

需要记录官方仓库、目标包、真实 README 路径、语言、不可变 ref/提交、快照路径、同步时间及内容摘要。候选优先在匹配 Demo 版本的官方资料中选中文；没有匹配版本时，可用官方当前分支中文并明确版本差异，再回退官方原语言。社区翻译与自行翻译只能另行标识。

正文原样存储于条目内的 `official/readme.md`，由平台统一发布与按需读取。更新是显式维护操作：核对来源 → 获取原文 → 检查 diff → 更新元数据；失败保留上一份可用快照。浏览器不直接依赖 GitHub API 限额。

专用的官方 Markdown 解析上下文，按上游 repo/ref/文件目录解析相对链接和锚点。保留清理后的内容、可见来源链接及读取原文入口。HTML 和远程图片采用明确的显示策略，不放宽现有 guide 的 URL/HTML 边界来迁就 README。

### 3. 官网预览

官网 URL 从官方仓库、包信息和文档交叉核对；无独立站点时说明并给官方仓库入口。

嵌入记录为允许、禁止或未知，带检查时间和依据。明确限制头是禁止依据；超时、接口失败属于未知。未见限制头仍需浏览器实测才可声称可嵌入。

iframe 只在官网页签活跃时挂载，带可读 title、no-referrer 和最小展示所需权限；独立于 F11/C13 执行 runner，不加入任意 origin 的消息执行协议。允许展示时仍保留官网直达按钮；禁止时给说明；未知时可尝试并保留重试/退出预览操作。不能仅凭 load、onError 或计时器认定成功或被禁止。

### 4. 条目整改批次

公共接线完成后，再逐库实施 1–3 Demo 和官方资料。优先纠正 D15 等错误结论与 E05 等文档/宿主偏差，再处理代表性的工具、交互、编辑器和 CLI。A06 当前用户修改独立保留，不作为可任意覆盖的旧版本。

每次只选明确条目；完成审查、修改、定向验证与复核后记录结果。其余库保持“尚未完成本轮整改”的状态，不能从样板或仓库 CI 扩推全库质量。

## Skill 与验收

`library-lab-quality` 支持审查和整改，默认审查。入口精简，内容设计、官方资料和验证标准按任务读取独立参考。全局安装只提供调用入口，Skill 每次定位当前仓库并读取适用规则。

每条内容分别检查：技术准确、解释清楚、Demo 有用、源码可迁移、官方来源可靠、结果可复核。每项给证据与 PASS/FAIL/NOT_RUN/BLOCKED；不以平均分抵消失败，适用项未验证不能报条目整体完成。内容评审不能代替现有 SDK/build/browser 收据。

## 验证场景

| 范围 | 验证内容 |
| --- | --- |
| Skill 安装 | frontmatter、引用、无未完成占位、安装目录与自动发现入口 |
| Skill 试用 | clsx 避免膨胀；Dexie 识别错误并核对来源；visualizer 使用真实 CLI 与报告解释 |
| Demo 协议 | 1/2/3 个有效场景通过，0/4 个或重复标识拒绝；原有三个场景兼容 |
| 导航 | 默认讲解、明确 Demo 深链接、无效场景回退、六页签切换 |
| README | 实际中文文件名、多包仓库、版本差异、相对路径、锚点、HTML/图片、失败保留旧快照 |
| 官网 | 允许/禁止/未知，超时与重试，load 失败仍触发，切换卸载及直达按钮 |
| 证据 | 政策测试不能写为 SDK PASS；无收据、指纹变化和缺专用套件准确保留状态 |

正文修改做内容、来源、链接和格式检查；示例修改跑对应条目；公共运行逻辑变化跑相关平台回归、typecheck、build 和关键浏览器流程。复用未受影响的检查，不因文档或 agent 切换反复全量测试。

## 实施边界

本方案不修改模板或 create-reactloom；Lab 保持私有。安装 Skill 不代表 README/iframe/1–3 Demo 平台功能已经落地。Skill 未获得平台改造范围时输出明确的前置依赖，并继续可独立完成的内容工作。提交、推送和发布依用户授权执行。
