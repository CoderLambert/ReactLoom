## 问题与处理

旧guide把Service Worker scope错当请求URL范围、说看不到其他源；把当前未使用的固定scope adapter当作正在运行的浏览器接线；AGENTS还保留“当前仍BLOCKED”的旧事实。讲解以历史验收起头、反例重复，且Node验证码顺序与浏览器相反，进阶HTTP503被笼统写成网络故障。

本轮围绕真实客户端请求→handler匹配→响应恢复组织三个独立目标：

| 场景 | 操作、观察与真实实现 |
| --- | --- |
| basic | GET文章42→参数匹配→200与文章body，输出真正request:match事件；浏览器同一canonical handler |
| business | 错码422/INVALID_CODE→正确码200/verified:true；Node与现有browser顺序一致；是固定验证码fixture |
| advanced | runtime handler once:true第一次503，第二次显式请求回canonical200；是HTTP响应而非传输拒绝，MSW不自动重试 |

Node新增requests(method/url/status/body)和真实MSW request:match(requestId/method/url)观察，断言匹配事件与完成请求逐项对应；finally统一resetHandlers/close。保留返回的既有摘要字段，已有测试继续可用。canonical handlers业务响应不变，routes仅改为等价模板字符串和正常排版。历史browser adapter与预检/注册/session gate策略保留行为，加注当前UI不导入它，未另造或复制第二个runner。
